# GloriaSetup rollout for ReactLab

Pushing a tag like `v1.2.0` runs `.github/workflows/release.yml`: it builds the Electron app, packs it with
`projectGloria/GloriaSetup@v0.1.0` and attaches `ReactLab_<version>_x64-setup.exe` to that release.

## Please

- **Check the version.** `package.json` says 1.0.0 and the GloriaLauncher catalog says 1.2.0. `gloria.toml` uses
  1.0.0 (the project file); the tag overrides it at release time. Bump `package.json` to match before tagging.
- **Check the data folders.** Electron stores settings under `%APPDATA%`, in a folder named after the app. The app
  never calls `setName` and `package.json` has no `productName`, so the folder is either `ReactLab` or
  `reactlab-desktop`. Both are listed in `data_folders`; remove the wrong one after looking at a real install.
  Uninstalling with "remove data" deletes them.
- **Icon.** `build/icon.ico` is gitignored and generated by `npm run icon`; the workflow runs that before packing.
  No icon file was added to the repo. Commit a `ReactLab.ico` and change `icon` if you prefer.
- **Build.** The workflow runs `electron-builder --win dir` and copies all of `release/win-unpacked` (the Electron
  runtime is needed at run time). NSIS and portable targets are no longer built in CI. Nothing was built locally, so
  the workflow is untested.
- **Legacy installs.** `legacy_names = ["ReactLab"]` matches the old NSIS install (productName `ReactLab`).
- **Secrets.** Set `WINDOWS_PFX_BASE64` and `WINDOWS_PFX_PASSWORD`; without them the setup is unsigned.
- `needs_webview2` is false because Electron bundles Chromium.

## Fix: release run did not attach the setup (v1.0.0)

- The failure `accepts at most 1 arg(s), received 2` came from the "Make sure the release exists" step in `.github/workflows/release.yml`: `gh release view <tag> -R <repo> *> $null` let `gh` see the redirection as an extra positional argument, so the step failed before GloriaSetup ran.
- Changed it to `gh release view <tag> -R <repo> --json id 2>&1 | Out-Null`, so the existence check still sets `$LASTEXITCODE` and no stray argument reaches `gh`.
- Not verified by a CI run; I inferred the cause from the error text and the workflow, and the log was not available here. Re-run the release after pushing.
